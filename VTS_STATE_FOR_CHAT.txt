## 1. WHAT THIS IS

VTS Portal — a private, dark "pro-terminal" PWA for one owner (Andrew, non-technical, on a
Mac; all building is done by Claude Code) plus admin-created users. One login fronts six
workspaces gated by role. Owner views a deployed site running `main`; a feature is only
visible after its PR is merged to `main` and the site redeploys.

- Version: **Alpha V 1.15** (`apps/web/src/meta/version.ts`).
- Branding: Vitalis Trading Systems LLC. Browser/app title: **"VTS Portal"**.

## 2. STACK

- npm monorepo (`workspaces: ["apps/api","apps/web"]`).
- Frontend: Vite + React 18 + TypeScript, **100% inline styles** (no layout CSS classes),
  responsiveness via `useResponsive()` JS hook (no media queries), theme objects in
  `src/theme/themes.ts`. Installable **PWA** (vite-plugin-pwa, auto-updating service worker).
- Backend: Fastify 5 + Drizzle ORM + `@libsql/client` (SQLite). Argon2id password hashing
  (`@node-rs/argon2`), server-side session cookies (only SHA-256 of token stored), Zod
  validation. Anthropic SDK `@anthropic-ai/sdk`. `web-push` for notifications.
- Money: integers — percentages in **basis points** (1350 = 13.5%), dollars whole. (Some
  trading price/qty fields are `real` floats: entryPrice, units, P&L.)
- The API also serves the built frontend (`apps/web/dist`), so the whole portal runs as ONE
  service.

## 3. INFRA / DEPLOY

- GitHub: `andrewr92896-ship-it/vts-portal` (private). Default branch `main`.
- Host: Railway (`railway.json`). Build: `npm install --include=dev && npm run build`.
  Start: `npm run start` → `node dist/server.js`. Healthcheck `/api/health` (timeout 100s),
  restart on failure (max 3).
- **Deploys trigger on merge to `main`** (Railway auto-deploys the tracked branch). Opening
  a PR does NOT deploy; merging does.
- Database: SQLite on a Railway **persistent volume**. Production `DATABASE_URL=file:/data/vts.db`.
  The DB client opens at process import (`apps/api/src/db/index.ts`); on boot the API runs a
  readiness probe + migrations + seeds. If the volume is missing/full/unmounted the API
  exits on boot ("crashed") and logs a clear `[db] Could not open the database …` message.
- On boot (production) it runs: `waitForDatabase()` → `runMigrations()` → `seedAdmin()` →
  `seedDemo()` → `seedWelcome()`, then starts market-news feeds and the background desk watch.

## 12. TRADING DATA FLOW (important for planning)

- Brokers supported (`trading/config.ts` BROKER_META): `ftp` (Funded Trading Plus /
  Match-Trader / funded prop), `oanda` (OANDA v20 / forex — fully wired, live API),
  `kraken` (Kraken Pro / crypto — connector present), `tradestation` (stocks — scaffolded),
  `manual` (hand-entered). FTP/TradeStation connectors are scaffolded; OANDA is the live one.
- **Live Wall** (`GET /api/trading/live`): desk-wide open positions, fetched live from every
  active connection; falls back to a sample feed when no connection exists.
- **Reconcile**: viewing the Live Wall (and a background "desk watch", prod + push only)
  upserts open positions into `trading_positions` and records closures to **History**;
  fires trade open/close push notifications.
- **Trade Log** (`GET /api/trading/trades`): merges hand-logged `trading_trades` AND
  broker `trading_positions` (open + closed). Broker rows are tagged + removable but not
  editable; hand-logged rows are editable+removable (owner; admins can remove anyone's).
- **History**: closed `trading_positions`, desk-wide, grouped by strategy/instrument.
- **Funded tab**: FTP prop challenge (`trading_challenges`) + funded/prop accounts
  (`funded_accounts`/`funded_trades`) + a "paste funded trades" screenshot importer.
- **Live Brokers tab** (`GET /api/trading/oanda-capital`): DESK-WIDE OANDA capital (NAV,
  balance, open P/L, daily/weekly/30-day trade P/L), each account attributed to its owner.
  Full-traders-only (view-only rejected).
- **Alerts**: TradingView posts to `/api/tv-webhook` (and `/api/webhooks/tradingview`),
  shared-secret gated; alerts can be analyzed by Claude. Paste a chart screenshot → analysis.

## 16. KNOWN QUIRKS / GOTCHAS

- PWA service worker caches the frontend; after a deploy a returning user may see the OLD
  bundle until the worker updates — fully close/reopen the app (iOS: swipe out of app
  switcher) or hard refresh. (The tab title is also set at runtime to beat this.)
- DB opens at import on the Railway volume; a missing/full/unmounted volume crashes the API
  on boot. Boot now logs a clear `[db] …` message and retries readiness.
- Inline styles only (no layout CSS), responsiveness in JS, money as integers (bp/whole $),
  per-user rows keyed by userId, Eastern-Time month bucketing for Kia. Drizzle migrations are
  pairs: the `.sql` file AND a `migrations/meta/_journal.json` entry.
- GitHub is reached only via `mcp__github__*` tools (no `gh` CLI). Headless browser is
  blocked → no screenshots; verify via typecheck/build + throwaway-DB scripts.
